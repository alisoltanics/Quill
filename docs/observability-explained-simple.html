Observability ساده و خیلی روشن

Observability یعنی چه؟

یعنی بفهمیم سیستم ما دارد چه کاری انجام می‌دهد، چه چیزهایی خراب هستند، و کجا باید نگاه کنیم.

  • سرویس‌ها درست کار می‌کنند یا نه؟
  • کدام سرویس کند شده؟
  • چند کاربر وصل هستند؟
  • CPU و RAM چقدر مصرف شده؟
  • Redis و Postgres خوب هستند یا نه؟

فلو اصلی پروژه

Gateway / Django / Redis / Postgres
        │
        │ هر کدام داده می‌سازند
        ▼
      /metrics endpoint
        │
        ▼
     Prometheus جمع‌آوری می‌کند
        │
        ▼
     Grafana نمایش می‌دهد

خیلی ساده: سرویس‌ها metric می‌سازند، Prometheus آن‌ها را می‌خواند، Grafana آن‌ها را روی نمودار نشان می‌دهد.

اولین کد: سرویس‌های اصلی به چه شکلی داده می‌سازند؟

در Gateway و Django ما endpointهایی مثل /metrics اضافه کردیم.

GET /metrics

یعنی این سرویس‌ها در پاسخ به این URL، اطلاعاتی مثل:

  • تعداد درخواست‌ها
  • زمان پاسخ
  • تعداد WebSocketها
  • تعداد خطاها
  • مصرف CPU/RAM

می‌فرستند. سپس Prometheus این صفحه را می‌خواند.

دومین کد: docker-compose چیست؟

ما در docker-compose.yml سرویس‌های زیر را اضافه کردیم:

  • Prometheus
  • Grafana
  • Redis Exporter
  • Postgres Exporter
  • Node Exporter
services:
  prometheus:
    image: prom/prometheus:v2.53.0
    ports:
      - "9090:9090"

  grafana:
    image: grafana/grafana:11.1.0
    ports:
      - "3001:3000"

  redis-exporter:
    image: oliver006/redis_exporter:v1.63.0
    ports:
      - "9121:9121"

  postgres-exporter:
    image: prometheuscommunity/postgres-exporter:v0.15.0
    ports:
      - "9187:9187"

  node-exporter:
    image: prom/node-exporter:v1.8.2
    ports:
      - "9100:9100"

این کد یعنی:

  • Prometheus شروع می‌شود و روی پورت 9090 گوش می‌دهد.
  • Grafana روی 3001 اجرا می‌شود.
  • Redis Exporter وضعیت Redis را می‌خواند.
  • Postgres Exporter وضعیت دیتابیس را می‌خواند.
  • Node Exporter وضعیت سرور را می‌خواند مثل CPU و RAM.

سومین کد: چرا Node Exporter اضافه کردیم؟

چون سرویس‌ها و دیتابیس‌ها فقط بخشی از داستان هستند. ما برای دیدن وضعیت ماشین/سرور هم باید CPU و RAM را ببینیم.

node-exporter:
  image: prom/node-exporter:v1.8.2
  ports:
    - "9100:9100"

این ابزار از خود سیستم می‌خواند:

  • CPU usage
  • RAM usage
  • load average
  • memory and disk status

سپس این داده‌ها را به Prometheus می‌دهد.

چهارمین کد: Prometheus دقیقاً چه کاری انجام می‌دهد؟

در فایل monitoring/prometheus.yml گفتیم Prometheus از کجا و چه چیزهایی را بخواند.

scrape_configs:
  - job_name: 'gateway'
    metrics_path: /metrics
    static_configs:
      - targets: ['gateway:8080']

  - job_name: 'document-service'
    metrics_path: /metrics
    static_configs:
      - targets: ['document-service:8000']

  - job_name: 'redis'
    metrics_path: /metrics
    static_configs:
      - targets: ['redis-exporter:9121']

  - job_name: 'postgres'
    metrics_path: /metrics
    static_configs:
      - targets: ['postgres-exporter:9187']

  - job_name: 'node'
    metrics_path: /metrics
    static_configs:
      - targets: ['node-exporter:9100']

این یعنی:

  • Prometheus هر 15 ثانیه به این آدرس‌ها سر می‌زند
  • از /metrics می‌خواند
  • مقادیر را ذخیره می‌کند
  • بعد Grafana می‌تواند همان داده‌ها را نمایش بده

خاموش/روشن کردن همهٔ observability با یک ستینگ

برای اینکه داده‌ها به‌صورت ناخواسته پر نشوند، یک متغیر یکپارچه اضافه کردیم:

OBSERVABILITY_ENABLED=false

وقتی این مقدار false باشد:

  • Jaeger خاموش می‌شود
  • Prometheus خاموش می‌شود
  • Grafana خاموش می‌شود
  • Redis exporter خاموش می‌شود
  • Postgres exporter خاموش می‌شود
  • Node exporter خاموش می‌شود
  • tracing در Gateway و Django هم غیرفعال می‌شود

یعنی فقط با یک خط می‌شود کل بخش monitoring را خاموش کرد تا داده‌ها پر نشوند.

OBSERVABILITY_ENABLED=true   # فعال
OBSERVABILITY_ENABLED=false  # غیرفعال

نحوهٔ اجرای دستوری هم این است:

OBSERVABILITY_ENABLED=false ./scripts/toggle-observability.sh

به زبان خیلی ساده:

GET http://gateway:8080/metrics
GET http://document-service:8000/metrics
GET http://redis-exporter:9121/metrics
GET http://postgres-exporter:9187/metrics
GET http://node-exporter:9100/metrics

پنجمین کد: Grafana چرا مهم است؟

Grafana فقط داده‌ها را نمی‌سازد؛ فقط آن‌ها را نمایش می‌دهد.

grafana:
  image: grafana/grafana:11.1.0
  ports:
    - "3001:3000"

Grafana به Prometheus وصل می‌شود و روی داشبوردها نمودار می‌کشد:

  • تعداد درخواست‌ها
  • زمان پاسخ
  • تعداد کلاینت‌های وب‌سوکت
  • مصرف CPU
  • مصرف RAM
  • وضعیت Redis و Postgres

چرا هر سرویس endpoint /metrics دارد؟

چون Prometheus فقط از یک استاندارد مشخص می‌فهمد: چیزی به اسم metric. اگر سرویس شما نبود، Prometheus نمی‌فهمد چه چیزهایی را بگیرد.

مثال:

# HELP gateway_ws_connections_number current open websocket clients
# TYPE gateway_ws_connections_number gauge
gateway_ws_connections_number 7

# HELP gateway_messages_received_total total websocket messages received
# TYPE gateway_messages_received_total counter
gateway_messages_received_total 128

این‌ها یعنی:

  • 7 کلاینت فعال هستند
  • در کل 128 پیام رسیده است

چه چیزهایی را جمع‌آوری می‌کنیم؟

منبع داده‌ای که می‌گیریم
Gateway WebSocket connections، پیام‌ها، درخواست‌ها، latency
Document Service درخواست‌ها، خطاها، saveها، زمان پاسخ
Redis Exporter memory، connections، health Redis
Postgres Exporter connection، status دیتابیس، health
Node Exporter CPU، RAM، load، disk

خلاصه خیلی کوتاه

Gateway داده می‌سازد

Django داده می‌سازد

Node/Redis/Postgres export دادهٔ سیستم را می‌گیرند

Prometheus داده‌ها را جمع‌آوری می‌کند

Grafana داده‌ها را روی داشبورد نمایش می‌دهد

اگر بخواهیم در یک جمله بگوییم

Observability یعنی این که سرویس‌ها اطلاعات بدهند، Prometheus آن‌ها را بگیرد، و Grafana آن‌ها را به صورت نمودار و داشبورد برای ما نشان بدهد.
