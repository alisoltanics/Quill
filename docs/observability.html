Observability — خیلی ساده و قابل فهم

هدف ما چیست؟

می‌خواهیم بفهمیم:

  • سرویس‌ها درست کار می‌کنند یا نه؟
  • خطاها کجا اتفاق می‌افتند؟
  • درخواست‌ها چقدر طول می‌کشند؟
  • WebSocketها چندتا active هستند؟
  • Redis و Postgres وضعیت خوبی دارند یا نه؟

Prometheus و Grafana دقیقاً چه هستند؟

Prometheus یک ابزار برای جمع‌آوری metricها است. یعنی از سرویس‌ها می‌خواند که مثلا: تعداد درخواست‌ها، زمان پاسخ، تعداد خطاها، تعداد WS connections، میزان مصرف Redis و Postgres چقدر است.

Grafana یک ابزار برای نمایش داشبورد است. یعنی همان داده‌هایی که Prometheus جمع‌آوری کرده را می‌گیرد و روی نمودارها و داشبوردهای خوانا نشان می‌دهد.

به زبان خیلی ساده:


Service -> /metrics -> Prometheus -> Grafana -> Dashboard

یعنی سرویس‌ها داده می‌سازند، Prometheus آن‌ها را می‌گیرد، Grafana آن‌ها را به صورت چارت و داشبورد نمایش می‌دهد.

CPU، RAM و این‌طور چیزها هم جمع می‌شوند

در پروژه ما فقط دادهٔ سرویس‌ها نیست؛ برای زیرساخت هم metric می‌گیریم. مثلا:

  • CPU usage
  • RAM usage
  • memory pressure
  • connection count
  • DB health
  • Redis memory and latency

این داده‌ها از exporters به Prometheus می‌آیند. در واقع:


Redis -> redis-exporter -> Prometheus
Postgres -> postgres-exporter -> Prometheus
System/host -> node-exporter -> Prometheus

در این پروژه، node-exporter برای CPU، RAM، load average و مصرف سیستم به Prometheus می‌فرستد. بعد Grafana این‌ها را روی داشبورد نشان می‌دهد تا ببینی سرور و دیتابیس در چه وضعیتی هستند.

ابزارها چه کاری انجام می‌دهند؟

1) Gateway (Go)

این سرویس اطلاعاتی مثل تعداد کلاینت‌های زنده، تعداد پیام‌ها، تعداد درخواست‌ها به Document Service و زمان پاسخ را ثبت می‌کند.

چیزهایی که ثبت می‌کند:

  • تعداد WebSocket connections
  • تعداد پیام‌های دریافتی
  • تعداد publish به Redis
  • تعداد درخواست‌های HTTP به Document Service
  • زمان پاسخ Document Service

2) Document Service (Django)

این سرویس هم وضعیت خودش را ثبت می‌کند:

  • تعداد درخواست‌ها
  • زمان پاسخ
  • تعداد saveهای سند
  • تعداد خطاهای save
  • تعداد publishها به Redis

3) Prometheus

Prometheus این داده‌ها را از سرویس‌ها می‌خواند و در خودش نگه می‌دارد.

کار اصلی: جمع‌آوری metricها.

4) Grafana

Grafana این داده‌ها را از Prometheus می‌گیرد و روی داشبورد نشان می‌دهد.

کار اصلی: نمایش داشبورد و نمودار.

5) Redis Exporter

از Redis داده می‌گیرد مثل memory، connection و وضعیت کلی Redis.

6) Node Exporter

از خود ماشین/컨테이ner داده می‌گیرد مثل CPU usage، RAM usage، load average و فضای دیسک. این بخش برای مشاهده وضعیت سرور و مصرف منابع خیلی مهم است.

7) Postgres Exporter

از PostgreSQL داده می‌گیرد مثل connection، query health و وضعیت دیتابیس.

فلوی سادهٔ observability

Gateway / Django / Redis / Postgres
          │
          │ ثبت metric و health
          ▼
       /metrics endpoint
          │
          ▼
      Prometheus
          │
          ▼
      Grafana
          │
          ▼
    داشبورد و نمودار

یعنی خیلی خلاصه:

  1. هر سرویس خودش metric می‌سازد
  2. Prometheus آن‌ها را می‌خواند
  3. Grafana آن‌ها را روی صفحه نمایش می‌دهد

Prometheus دقیقاً چطور داده را جمع‌آوری می‌کند؟

Prometheus به‌صورت دوره‌ای (scrape) به URLهای /metrics سرویس‌ها می‌رود و مقدار metricها را می‌خواند.

به زبان ساده:


Gateway code:
    counter = 12
    /metrics -> gateway_messages_received_total 12

Document Service code:
    counter = 7
    /metrics -> document_service_http_requests_total 7

Prometheus:
    every 15s -> GET http://gateway:8080/metrics
    every 15s -> GET http://document-service:8000/metrics
    save values in its time series DB

یعنی Prometheus می‌گوید:


GET http://gateway:8080/metrics
GET http://document-service:8000/metrics
GET http://redis-exporter:9121/metrics
GET http://postgres-exporter:9187/metrics

بعد از آن، این داده‌ها در Prometheus ذخیره می‌شوند و Grafana می‌تواند آن‌ها را بخواند.

کدام ابزار چه چیزی را ذخیره می‌کند؟

ابزار چه چیزی ثبت می‌کند
Gateway WebSocket connections، پیام‌ها، درخواست‌ها به Document Service، latency
Document Service درخواست‌ها، saveها، خطاها، timing
Prometheus metricها را جمع‌آوری و ذخیره می‌کند
Grafana metricها را روی داشبورد نمایش می‌دهد
Redis Exporter وضعیت Redis مانند memory و connection
Postgres Exporter وضعیت PostgreSQL مثل connection و health

چرا این‌ها مهم هستند؟

بدون این ابزارها، فقط می‌فهمی سرویس «خراب» است؛ اما نمی‌دانی:

  • کدام سرویس مشکل دارد؟
  • خطا از کجا شروع شد؟
  • چه چیزی کند شده؟
  • چند کاربر وصل هستند؟
  • Redis یا Postgres دچار مشکل شده‌اند؟

خلاصهٔ خیلی کوتاه

Gateway / Django = metric تولید می‌کنند

Prometheus = metricها را می‌خواند

Grafana = metricها را نمایش می‌دهد

Redis/Postgres exporter = وضعیت زیرساخت را به Prometheus می‌دهند
